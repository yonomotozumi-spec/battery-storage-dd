# 蓄電池案件 DDチェックシート（PX準拠）

系統用蓄電池の用地デューデリジェンスをブラウザだけで行えるスクリーニングツールです。
インストール不要・サーバー不要・入力データはブラウザ外に送信されません（完全クライアントサイド）。

画面は3つあります。

| ページ | 用途 |
|---|---|
| `index.html` | 用地が決まっている案件のDDチェック（許認可17項目＋系統・スケジュール・コスト） |
| `substation.html` | **候補地の緯度経度から最寄りの変電所を検索し、系統スコア＋近接スコアで採点**（用地を探す段階）。全国の変電所を**地図に表示**し、クリックで**上位系統（つながる送電線・相手側の変電所・上位系の制約設備）**をたどれる |
| `ordinance.html` | **蓄電池条例リスクDB**（独立ツール）。直近の公表・施行の注意喚起、全国台帳の検索、案件所在地の照合、開発許可権者151者の調査状況 |

`index.html` と `substation.html` はヘッダーのリンクで相互に行き来でき、入力済みの緯度経度は
そのまま引き継がれます。`ordinance.html` はDD・変電所スコアとは切り分けた独立ページです
（単体で共有・公開できる。ナビゲーションリンクなし）。

## 使い方（Web）

`index.html` をブラウザで開くだけで使えます。公開URLにアクセスした場合も同じです。

1. **基本情報**を入力（緯度経度を推奨。座標から確認マップのリンクが自動生成されます）
2. **A. 系統変数**（空き容量・先行申込・電圧階級・ノンファーム・検討区分）を選択
3. **B. 許認可事前確認**（PX 17項目）の確認状況を記録
4. **C. スケジュール / D. コスト**を選択
5. **「DDチェックを実行する」**で総合スコア（0〜100）・判定・リスク項目一覧を表示
6. **「grid.json をダウンロード」**で回答を書き出し、xlsx生成スクリプトに連携

### スコアリング

| カテゴリ | ウェイト |
|---|---|
| A. 系統変数 | 40% |
| B. 許認可事前確認 | 30% |
| C. スケジュール | 20% |
| D. コスト | 10% |

判定：75点以上=進行推奨 ／ 45〜74点=要確認事項あり ／ 44点以下=リスク高・再検討推奨

## 座標から許認可を自動判定（reinfolib）

許認可17項目のうち `○`（API）が付く7項目（浸水・土砂災害・液状化・市街化区域・市街化調整区域・用途地域・自然公園）は、
国交省 不動産情報ライブラリ（reinfolib）の座標判定を取り込んで**自動で確認状況を埋められます**。
APIキーの秘匿とCORSの都合上、API取得はスクリプト側（`reinfolib_judge.py`）で行い、Web画面はその結果JSONを読み込む方式です。

1. Webツールに**緯度経度を入力**する
2. APIキーを環境変数に入れて `run` を実行する（GeoJSONの取得と判定を一度に行い、values.json を出力）

```bash
export REINFOLIB_API_KEY=...        # キーはリポジトリに置かない（保管場所はNotionのナレッジページ）
python scripts/reinfolib_judge.py run --lat 42.9270 --lon 141.2698 --out values.json
```

取得と判定を分けたい場合（取得済みGeoJSONを再利用する・ネットワークの無い環境で判定だけ行う）:

```bash
# ① 取得URLを一覧化（ブラウザで開いて保存する場合）
python scripts/reinfolib_judge.py urls --lat 42.9270 --lon 141.2698 --key <APIKEY>
# ①' またはAPIから直接取得して <reinfolibdir>/<コード>.geojson に保存
python scripts/reinfolib_judge.py fetch --lat 42.9270 --lon 141.2698 --dir <reinfolibdir>
# ② 点内判定（ネットワーク不要）
python scripts/reinfolib_judge.py judge --lat 42.9270 --lon 141.2698 \
  --dir <reinfolibdir> --out values.json
```

APIキーが無効なときは `HTTP 401/403` で止まります（キーそのものは出力しません）。取得に失敗した
レイヤは values.json の `missing` に入り、該当項目は手入力のままになります。

3. Web画面の **B. 許認可事前確認 → 「📥 自動判定JSONを読込」** で `values.json` を選択すると、
   対象7項目のプルダウンが座標判定に応じて自動セットされ、検出値がインラインで表示されます

> 自動判定はスクリーニング補助です。プルダウンは手動で上書きでき、最終確認は各行政窓口・地図の目視で行ってください。

## xlsxチェックシート生成（scripts/）

Webツールの回答（grid.json）を取り込んで、5タブ構成のPX案件チェックシートを生成できます。

```bash
pip install openpyxl
python scripts/build_px_checksheet.py \
  --address "北海道札幌市南区簾舞" --lat 42.9270 --lon 141.2698 \
  --muni "札幌市" --pref "北海道" --pxno "PE-XXXX" --tanto "担当者名" \
  --tso "北海道" --grid grid.json \
  --out "PX案件チェックシート_地名.xlsx"
```

タブ構成：**総合評価**（自動集計・COUNTIF数式で入力に連動）／許認可事前確認DD（17項目）／許認可チェックシート（39法令）／輸送確認／**系統接続確認**（12項目）

サンプル出力は `docs/` を参照。

## 変電所スコアリング（scripts/）

全国変電所リスト（66kV以上）のxlsxを読み込み、接続検討の実回答12件から校正した配点
（変電所スコアリング v1 2026-07-28）で全変電所を「接続検討を申し込む価値」の順に点数化します。
高圧2MWの系統用蓄電池を前提としたスクリーニングです。

```bash
pip install openpyxl
python scripts/score_substations.py \
  --in "data/全国変電所リスト_66kV以上.xlsx" \
  --out "変電所スコアリング.xlsx"
```

タブ構成：**スコアリング**（全行のゲート判定・S1〜S6・系統スコア・ランク・実績メモ。全て数式で入力に連動）／
**スコアリング基準**（配点パラメータ表。黄色セルを変えると再計算）／**実績DB**（接続検討回答の実績102件＝手入力18件＋検証一覧からの取込84件、＋分析メモ）

### スコア構成（系統スコア80点）

| 記号 | 変数 | 配点 | 閾値・ルール |
|---|---|---|---|
| S1 | 空容量(上位系考慮) | 35 | ≧20MW:35 ／ ≧6MW:28 ／ >0:15 ／ ≦0:0 |
| S2 | N-1電制 可否 | 10 | 可:10 ／ それ以外:0 |
| S3 | 予想潮流の余裕(\|潮流\|/運用容量) | 15 | ≦30%:15 ／ ≦60%:9 ／ ≦90%:4 ／ >90%:0 |
| S4 | 出力制御可能性 | 5 | なし:5 ／ 有り:0 |
| S5 | 配電用変電所か(二次電圧) | 10 | 二次≦7kV:10 ／ その他数値:5 ／ 不明:0 |
| S6 | エリア | 5 | 実績工期からの仮置き（九州・北海道5〜中部・沖縄2） |

**ゲート（⚠警告）**: 空容量(上位系考慮)≦0 かつ N-1電制≠可 → 「⚠上位系0」の警告を付ける。ランクは通常どおり算出する
（S1が0点なので最高45点＝B止まり）。2026-10-20までは「除外」としてランク計算から外し画面にも出していなかったが、
喜多方（上位系増強で工期10年2ヶ月）と同じ公表値（上位系0・N-1不可）の北海道・由仁が410万円・6ヶ月で連系した実績があり、
上位系0はノンファーム接続の混雑を示すだけで増強必須とは限らないため、隠さずに警告を付けて見せる方式に変更した。

**ランク**: S:60点以上 ／ A:48〜59 ／ B:36〜47 ／ C:35以下 ／ データ無:空容量未公表（ゲート該当は別途「警告」列）。
ランクS/Aの変電所を優先し、その周辺（目安2km以内・既設高圧配電線の近く）で土地を探して接続検討を申し込む使い方を想定。
土地確定後に近接性S7（20点）を加えて100点満点で最終評価します。

サンプル出力は `docs/変電所スコアリング_全国66kV以上_v1.xlsx` を参照。

### 接続検討回答の実績DBへの取込（scripts/import_connection_results.py）

「接続検討回答 検証一覧」xlsx（回答書1件=1行。`data/接続検討回答_検証一覧.xlsx`）を実績DBに取り込みます。
`集計対象` が ○ の行（案件ごとの最新回答）を `data/connection_results.json` に書き出し、
`substation_scoring.py` が手入力の実績の後ろに追加します。xlsx版の実績DBタブ・スコア表の実績メモと、
Web版の実績表示（同じ変電所に複数の回答があれば全件）に反映されます。

```bash
python scripts/import_connection_results.py \
  --in "data/接続検討回答_検証一覧.xlsx" \
  --list "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out data/connection_results.json
# 取込後に xlsx と Web用JS を再生成
python scripts/score_substations.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out "docs/変電所スコアリング_全国66kV以上_v1.xlsx"
python scripts/build_substation_web_data.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out data/substations.js
```

- 変電所名は、回答書の「変電所」欄の先頭が全国変電所リストの名前と一致するときだけリスト表記に揃えます（84件中41件）
- 回答書に変電所名が書かれていない行（東北電力の高圧版回答書など）は、設置場所の住所を国土地理院ジオコーダで
  緯度経度に変え、最寄りの変電所（同エリア・最大電圧154kV未満・二次電圧22kV以下または不明・5km以内）を
  **推定**として紐づけます（33件）。要約に「(変電所は推定)」、教訓欄に距離と次点の変電所を明記します。
  確定は回答書の別紙「工事概要図」で行ってください。住所→座標の結果は `geo_cache/connection_sites.json` に保存
- どちらにも当てはまらないもの（10件：雫石・犀川・大崎(中国)など名前は分かるがリストに無い配電用変電所、
  5km以内に候補が無いもの）は「－(原文)」として実績表には載りますが、変電所の検索結果には紐づきません
- 手入力の実績と同じ案件（伊勢市特高・南関町・喜多方No071）は二重にしないよう除いています
- 取込分はAIで回答書PDFを読み取った値です。配点（S6エリア点など）の校正には使っていないので、判断の前に原本で確認してください

## 変電所スコア検索（Web / substation.html）

`substation.html` をブラウザで開き、**候補地の緯度経度を入力すると最寄りの変電所を検索**して、
系統スコア80点に近接スコアS7（20点）を加えた**総合スコア100点**で採点します。
Googleマップで開いた地点のURLを「まとめて貼り付け」欄に貼れば座標を自動で分解します。

1. 緯度経度を入力（`index.html` から遷移すると自動で引き継がれます）
2. 検索範囲（5〜50km／全国）と並び順（総合スコア順／距離順／系統スコア順）を選ぶ
3. 候補変電所が総合スコア順に並ぶ。行をクリックするとS1〜S7の内訳・空容量・N-1電制・接続検討の実績が開く

### 上位系の確認済み／未確認の区別

S1（空容量）とゲートは「空容量(上位系考慮)」で判定しますが、中部・四国・東北・北陸・沖縄は上位系を単独で公表していないため
「当該設備」の空容量で代用しています。代用した変電所は上位系の空きが0でも警告が付かず、ランクが甘く出る可能性があります
（2026-10-20時点のS/A 1,384件のうち、上位系で判定できたのは361件、代用は1,023件）。

上位系を公表していないエリアは「取り方」の問題ではありません（2026-10-20確認）。東北・四国のCSVには「空容量(上位系等考慮)」の列が
あるものの配電系の全行が「－」、北陸のCSVには上位系の列そのものが無く、中部は公式CSVを取り込んでいる蓄電所ネットでも上位系は
「情報なし」です。接続検討の回答でしか分かりません。北海道は2026-10-20からPDFの読み取りで上位系を判定できるようになりました
（後述「スコア元データの定期更新」）。

**上位系の「推定」も見送り（2026-10-20に検証）**。「上位系考慮＝当該設備と上流設備の空容量の小さい方」という考え方で推定できないか調べたが、
推定値の答え合わせができる公表データが無い。関西は上位系の数値を公表しているが上流設備は「対象／ー」の印だけ（設備番号なし）、
九州・北海道は設備番号があっても上流の送電線の空容量が「―」。関西の配電用1,295バンクで印と出力制御の有無だけから推定すると、
「上流設備＝対象 かつ 出力制御有り」の533件は86%が上位系0だが、「印なし・出力制御なし」の762件でも33%が上位系0で、
全体の的中は約73%にとどまる。一方、東北は配電用669バンクの98%（657件）が「上流設備あり・出力制御有り」なので、
この推定を使うと東北のS1はほぼ全て0点になり、86%の確からしさで採点が一変してしまう。出力制御有りはS4で既に減点しているため、
推定上位系は導入せず「上位系未確認」の表示で注意喚起するにとどめる。

画面ではランクの横に **上位系✓**（上位系考慮で採点）／**上位系未確認**（当該設備で代用）を表示し、内訳にも注意を出します。
座標検索の「上位系の空容量を確認できた変電所だけ表示」にチェックすると、確認済みだけに絞れます。

### 都道府県から一覧・CSV出力

画面上部の切り替えで「📍 場所から検索」と「🗾 都道府県から一覧・CSV」を選べます（`substation.html#pref` で直接開けます）。
後者は**候補地の座標が無くても**使えます。

1. **都道府県を選ぶ（複数可）**：エリアごとにまとめて並び、エリア名のチェックでそのエリアの県をまとめて選べます。
   何も選ばなければ全国が対象。都道府県は変電所の座標から求めた所在地です（座標が無い変電所は元リストの都道府県、どちらも無いものは「都道府県不明」）
2. **変電所の種類**：「良い変電所（S・A）だけ」「全変電所」のボタン、または系統ランクのチェックで選ぶ
3. 任意で、上位系の確認（すべて・確認済みのみ・未確認のみ）／空容量の下限MW／N-1電制「可」だけ／出力制御「なし」だけ／座標がある変電所だけ／
   市区町村（都道府県を1つだけ選んだとき）／地域・名前のキーワード（部分一致・カンマ区切り）
4. 「一覧を表示」で上位100件を表示、「CSVで保存」で該当全件を保存（Excelでそのまま開けるBOM付きUTF-8。
   ファイル名は `substations_3pref_SA_2026-10-19.csv` のように半角）

座標検索の結果も、表の下の「この検索結果をCSVで保存」で距離・S7・総合スコア付きで全件保存できます。

### 地図で見る・上位系統をたどる（substation.html#map）

画面上部の「🗺 地図で見る・上位系統をたどる」で、座標のある全変電所（5,414件）を地図（地理院タイル）に表示します。
丸の色は系統ランク、大きい丸は154kV以上（上位系側）、橙の縁は上位系の空容量が未確認（当該設備で代用）の変電所です。
ランク・上位系の確認・空容量の下限・電圧階級・N-1電制・出力制御で絞り込めます。地図ライブラリ（Leaflet）と地図タイルは
インターネットから読み込むため、オフラインでは地図だけ使えません（ほかの機能は影響なし）。

丸をクリックすると、その変電所のスコア内訳・系統データに加えて **「上位系統・つながり」** を地図の下に表示します。

| 内容 | 出どころ |
|---|---|
| 変圧器（バンク）ごとの運用容量・予想潮流・空容量（当該／上位系）・N-1電制・出力制御・制約要因 | 各社の変圧器CSV |
| **上位系の制約設備**（平常時出力制御の要因になりうる上位系設備。送電線名・変電所名に引き当て済み） | 変圧器CSV・送電線CSVの「上位系設備」欄 |
| **つながっている送電線**と**相手側の変電所**（kV・運用容量・予想潮流・空容量・N-1電制。上位側／下位側の目印付き） | 送電線CSVの「潮流方向」欄の両端 |

**上位系統の状態の色分け**：丸の色は既定で「上位系統の状態」です（プルダウンで系統ランク色に切替可）。

| 色 | 状態 | 判定 |
|---|---|---|
| 緑 | 上位系に空きあり | その変電所の「空容量(上位系考慮)」が公表されていて 0 より大きい |
| 赤 | 上位系がダメ（空き無し） | 「空容量(上位系考慮)」が 0 以下。または未公表で、上位側の変電所の該当バンク（この送電線の電圧を二次側に持つ変圧器）が全て空き 0 以下 |
| 黄緑 | 上位側に空きあり | その変電所の上位系値は未公表だが、上位側の変電所の該当バンクに空きがある（混在を含む） |
| 橙 | 上位系統が不明 | 上位系値も上位側の変電所の値も非公表（東北・北陸・四国・中部・沖縄に多い） |
| 灰 | 空容量データ無し | 送配電事業者の空容量が未取得（OSM由来の行） |

「上位系の確認」のプルダウンで「上位系がダメのものだけ」に絞れます。内訳の「上位系統・つながり」には判定と理由（どの送電線・変電所の値で判断したか）を出し、
空容量 0 以下の値と、上位系の制約設備のうち空き 0 以下のものを赤で示します。

**上位系統の送電線を描く**：「上位系統の送電線を描く（6エリア・模式線）」をオンにすると、両端が座標のある変電所に引き当たった送電線
（154kV以上 358本／66kV以上すべてで 2,294本）を地図全体に描きます。線の色は、送電線自体の空容量（変電所間ではほぼ非公表）→
電圧の高い側の変電所の該当バンクの空容量 → それも非公表なら電圧の低い側（その線にぶら下がる側）の変電所の「空容量(上位系考慮)」の順で判定し、
緑＝空きあり・赤＝空き無し・灰の破線＝非公表。太さは電圧です。線をクリックすると下位側の変電所を選びます。
端点が分岐・発電所・需要家の線や座標の無い変電所への線は描けません。

> 上位側の変圧器（二次側が 66kV 以上のバンク）の空容量は、6社とも公表物でほぼ「-」（非公表）です。上位系の空きが数値で分かるのは、
> 各変電所の「空容量(上位系考慮)」を公表している関西・中国・九州（と東京・北海道）だけで、東北・北陸・四国は「不明」になります。

相手側の変電所名をクリックするとその変電所に移り、さらに上位をたどれます。地図には相手側までの**模式線**（公表CSVの両端を直線で結んだもの。
実際の送電線の経路ではない）を引き、「2段先まで」で相手側のつながりも細線で重ねます。
「場所から検索」の内訳にも同じ「上位系統・つながり」の欄と「🗺 地図で系統のつながりを見る」リンクがあり、
検索結果の「🗺 この範囲を地図で見る」で候補地と検索範囲の円を地図に出せます。

対象は、全国共通形式のCSVを公開している **東北・北陸・関西・中国・四国・九州** の6エリア（本体リストの2,880行に付与。
生成方法は下記「系統トポロジーの生成」）。東京・中部・北海道・沖縄は公表物を自動取得できないため、つながりの情報はありません。
中部だけは「中部電力PG公表の送電線・変電所（実形状）」をオンにすると、公表マッピングのGeoJSON（`chuden_cache/`）から作った
送電線4,128本・地点2,505件（2026-08-13時点）を実形状で重ねられます（`scripts/build_chuden_grid_web.py` → `data/chuden_grid.js`。
オンにしたときだけ約1MBを読み込み）。

> 各社の「系統空容量マッピング」は中部を除き模式図のPDFで座標を持たないため、送電線の実形状を地図に出せるのは中部だけです
> （調査結果は「他エリアの座標が自動取得できない理由」）。他の5エリアは、公表CSVの「潮流方向」から**つながり（どの変電所と
> どの送電線で結ばれているか）だけ**を取り出し、変電所の座標どうしを直線で結んでいます。

### 系統トポロジー（上位系統のつながり）の生成（scripts/build_grid_topology.py）

6社が公表している変圧器CSVと送電線CSV（OCCTOの共通フォーマット）を `grid_cache/` に取得し、
変電所ごとの「つながる送電線」「相手側の変電所」「上位系の制約設備」を引き当てて `data/grid_topology.js` を作ります。

```bash
# ① 取得（要ネットワーク。取得済みのCSVは grid_cache/ に同梱）
python scripts/build_grid_topology.py fetch --cache-dir grid_cache
# ② 生成（ネットワーク不要）
python scripts/build_grid_topology.py build --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \
  --cache-dir grid_cache --out data/grid_topology.js --report "docs/系統トポロジー_照合レポート.md"
```

引き当てのルール（推測で埋めない）:

- **本体リストとの紐づけ**：エリア内で、種別（変電所／開閉所）を外した名前が一致する行（`update_capacity.py` と同じ）。
  「ヶ／ケ」、先頭のアポストロフィ、「黒瀬（変）」「滑川開」のような略記は吸収する
- **送電線の両端**：「潮流方向」欄（例: `青森変電所→瀬辺地変電所`／`変1→変6`／`A→B`／九州は自・至の2列）を、同じ公表物の
  変電所No（四国・関西）または変電所名（東北・北陸・中国・九州）に引き当てる。四国の「徳島変3」のような県付きの番号は、
  そのファイルの変電所が本体で最も多く属する県で解決する。変圧器CSVに無いが本体リストにはある設備（開閉所など）は
  端点から拾って名前だけのノードにする（座標があれば線を引ける）
- 引き当てられない端点（発電所・需要家・○○線分岐・開放点など）は**文字のまま残す**
- **上位系の制約設備**：各社の設備番号（東北 `送0104`・`変002`、北陸 `H012`・`TSS001`、中国 `基L22`、四国 `基変31`・`基送27,28,29`、
  九州 `19地区送電線№6`・`変電所No1(1)`）を同じ公表物の送電線名・変電所名に引き当てる。フェンス名などはそのまま残す

結果は [`docs/系統トポロジー_照合レポート.md`](docs/系統トポロジー_照合レポート.md)（エリアごとの件数・引き当てられなかった端点）。
初回（2026-10-20）は変電所ノード3,730件・送電線6,593本、本体リストの2,880行に紐づき、端点の引き当て率は関西・九州・四国で8〜9割、
東北は分岐・需要家が多く半分弱です。毎月5日の `capacity-refresh` で公表CSVを取り直すたびに再生成します。

| リンク | 内容 |
|---|---|
| [系統連系診断](https://bess-net.jp/tools/grid-connection-check) | 都道府県・出力(MW)・容量(MWh)を入れると連系候補Top5を100点満点で表示。URLに条件を含められる（例: [秋田県・12.5MW・50MWh](https://bess-net.jp/tools/grid-connection-check?pref=%E7%A7%8B%E7%94%B0%E7%9C%8C&mw=12.5&mwh=50)） |

画面での使い方：

1. 候補地の座標で検索すると、「外部の参考DB」の都道府県が**最寄り変電所の県に自動で切り替わる**。出力(MW)・容量(MWh)は既定 12.5MW／50MWh で、書き換えるとリンクのURLがその場で変わる
2. 候補変電所の行を開くと、内訳の下に「🔎 蓄電所ネットで『○○』を検索」「⚡ 蓄電所ネット 系統連系診断（県・MW／MWh）」のリンクが出る。
   名称検索は蓄電所ネット側が「横手」のように施設種別なしで登録している地域があるため、末尾の「変電所」「開閉所」を落として部分一致で引く

本ツールと蓄電所ネットの違い（2026-10-13 確認、蓄電所ネットの最終更新 2026-10-12）：

| 項目 | 本ツール | 蓄電所ネット 系統連系診断 |
|---|---|---|
| 収録 | 6,071変電所（66kV以上・10社） | 8,346変電所（10社） |
| 座標 | 5,329件（87.8%）。候補地からの直線距離で検索 | 1,082件（主に中部）。座標が無い変電所は同じ都道府県内をまとめて検索 |
| 空容量の見方 | 「上位系考慮」を優先。≦0かつN-1電制不可は**⚠上位系0の警告**（S1=0でB以下） | 「当該設備」÷出力の比率で加点（1.5倍+30／1.0倍+20／0.5倍+10）。上位系の制約・ゲートは無い |

> **読み方の注意**：蓄電所ネットは当該設備の空容量だけで点数を付けるため、上位系の空きが0の変電所

>
> **秋田県・12.5MW／50MWhの例**：蓄電所ネットのTop5は 横手・花輪・角館・牛島・御所野（いずれも45点「連系困難」、出力制御あり）。

### 変電所座標の追加（OSM / scripts/fetch_substation_coords.py）

座標が未取得の変電所（全6,071件中2,924件）に、OpenStreetMapから実測座標を付与します。
取得（要ネットワーク）と反映（ネットワーク不要）を分けているので、Overpass APIに到達できない
環境ではキャッシュだけ別環境で取得して持ち込めます。取得済みのキャッシュ（33都道府県＋全国名称検索）は
`osm_cache/` に同梱しているため、`apply` だけならネットワーク無しで再現できます。
元リストは `data/全国変電所リスト_66kV以上.xlsx` に同梱しているので、そのまま実行できます。

```bash
# ① 取得：都道府県ごとにOSMの変電所を取得してキャッシュ（Overpass APIへの接続が必要）
python scripts/fetch_substation_coords.py fetch \
  --in "data/全国変電所リスト_66kV以上.xlsx" --cache-dir osm_cache

# ② 反映：キャッシュと名称を突き合わせて座標を書き込む（ネットワーク不要）
python scripts/fetch_substation_coords.py apply \
  --in "data/全国変電所リスト_66kV以上.xlsx" --cache-dir osm_cache \
  --out "data/全国変電所リスト_66kV以上_座標追加.xlsx" --report coord_report.csv

# ③ 座標が増えたらスコアリングxlsxとWeb用データを再生成
python scripts/score_substations.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out "docs/変電所スコアリング_全国66kV以上_v1.xlsx"
python scripts/build_substation_web_data.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out data/substations.js
```

**推測で座標を埋めません。** 一致しなかった行は空欄のままにします（近接スコアS7は500m〜5kmの
刻みで判定するため、都道府県の代表点のような数十km誤差の推定値を入れると距離評価が破綻するため）。

照合のルール：

- 都道府県内に限定して照合（同名の変電所が全国に多数あるため）。都道府県が不明な行は全国検索し、候補がちょうど1件のときだけ採用
- リストの県に候補がまったく無いときだけ**隣県**も探す（元リストの都道府県は所在地と隣県でずれる行があるため。後述）。隣県の候補は、一意・エリアの実測分布内・名称に他社名なし・**リストの県の既存座標から10km以内**をすべて満たすときだけ採用
- 名称は事業者名プレフィックス・法人格・連番（①など）・空白を除いて正規化。**施設種別（変電所／開閉所／変換所）は区別したまま**照合する（「芳賀変電所」と「芳賀開閉所」の取り違えを防ぐため）
- 種別が一致しない場合のみ種別を外した緩い照合に落とすが、候補が一意のときだけ採用
- 同名候補が複数ある場合は、リストの最大電圧と一致するOSM候補がちょうど1件のときだけ採用。決められなければ見送り
- 全国検索の結果は、その行のエリアの実測分布（既存のOSM実測座標から算出）から外れていたら採用しません。OSMに未登録の変電所が他エリアの同名施設を一意ヒットとして拾ってしまうため（例: 関西「稲美変電所」に北海道の座標）
- 正規化して固有名が残らない名前（「6203変電所」のように名前自体が数字のもの）は照合に使いません。OSM側の名無しの「変電所」と同じキーになるため
- 付与した行の座標精度は `OSM実測(名称一致)` になり、Web版の内訳に「同名の別変電所の可能性が残る」旨が表示されます
- `--report` で全行の照合結果（一致／特定不可／エリア外で不採用／一致なし、OSM側の名称）をCSVに出力

OSMからの取得だけでの到達点は **座標あり3,195件 / 6,071件（52.6%）** でした。残る2,876件はOSMに登録が無く、
`power=substation` タグを外した名称検索でも上位7県で1.9%しか追加で拾えなかったため、
各社の系統情報公表資料に当たる必要があります。中部エリアはこれを済ませており（後述の
`fetch_chuden_coords.py`）、他エリアは Google Places で補完したため（後述の
`fetch_google_coords.py`）、現状は **座標あり5,329件（87.8%）** です。

### 座標調査の優先リストと反映（scripts/list_missing_coords.py, merge_coords.py）

残った未取得行のうち、**ランクS/A（系統スコア48点以上）で上位系0の警告が無いもの**だけを

`--defer` に指定したエリア（販売が難しいエリアなど）は別シートに分けます。

```bash
# ① 優先リストを出力（優先S_A / 劣後S_A / 都道府県別 の3シート）
python scripts/list_missing_coords.py \
  --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \
  --out "docs/座標未取得_優先リスト.xlsx" --defer 四国 --defer 北陸

# S/A以外も含めた作業リスト（候補地の見送り判定用に座標だけ揃える）
python scripts/list_missing_coords.py \
  --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \
  --out "docs/座標未取得_残り全件.xlsx" \
  --ranks "S,A,B,C,データ無" --include-gated

# ② 調べた座標を緯度・経度欄（黄色）に記入したら、本体xlsxへ戻す
python scripts/merge_coords.py \
  --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \

  --out "data/全国変電所リスト_66kV以上_座標追加.xlsx" --report merge_report.csv

# ③ スコアリングxlsxとWeb用データを再生成
python scripts/score_substations.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out "docs/変電所スコアリング_全国66kV以上_v1.xlsx"
python scripts/build_substation_web_data.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --out data/substations.js
```

突き合わせは **No.**（本体xlsxの通し番号）で行うため、優先リストのNo.列は消さないでください
（エリア＋変電所名は13組が重複しておりキーにできません）。記入した座標は次の場合に採用されません
（理由は `--report` のCSVに残ります）。

- No.と変電所名が一致しない（No.の書き間違い・行ズレの検出）
- 緯度・経度のどちらかが空、または数値でない
- 日本の範囲外（緯度と経度を逆に書いた場合もここで落ちます）
- そのエリアの実測分布から外れている（`--allow-outside-area` で警告扱いにできます。後述）
- 既に座標がある（`--force` で上書き可）

採用された行の座標精度は既定で `公表資料(手動)` になります。出所が違うときは `--acc` で変えてください（例: `--acc "Google Places(名称一致)"`）。

エリア分布の判定は既存の実測座標から作るため、参照点が地理的に偏っているエリアでは正しい座標でも
外れることがあります（例: 三重県南部の参照点が無いため、熊野市の賀田変電所 33.97 が中部の下限
34.04 を下回る）。出所が明確な座標を採る場合は `--allow-outside-area` を付けると採用され、
レポートに「要確認」として残ります。既定はオフです。

### 元リストの都道府県のずれ（2026-10-19 調査）

座標から引いた所在地（国土地理院の逆ジオコーダ）と元リストの「都道府県」を比べると、**170件が食い違い、すべて隣県**でした。
すべて元リストに最初から入っていた「OSM実測」の行で（OSM実測2,718件の6.3%）、東京エリア94件・関西22件・東北21件・九州15件など。
例: 上野変電所（台東区）が「埼玉県」、練馬変電所（練馬区）が「埼玉県」、鹿折変電所（気仙沼市）が「岩手県」。
元リストの都道府県は所在地ではなく**管轄（支社）の区分**と考えられます。

影響と対応:

| 箇所 | 影響 | 対応 |
|---|---|---|
| 画面・CSVの都道府県 | 所在地と違う県で検索に出る | 座標から引いた都道府県を優先（元リストの値は「元リストの都道府県」列に残す） |
| OSM照合（fetch_substation_coords.py） | リストの県だけ探すので、隣県にある変電所を取りこぼす | 候補が無いときだけ隣県も探す（上記の照合ルール）。既存キャッシュでの試算は新規0件（隣県で一致した2件はどちらも別施設で、ガードで不採用：神奈川県の日吉→中部電力の日吉〔静岡県〕、長野県の田島→埼玉県の田島）。隣県のキャッシュが無い県（兵庫・滋賀・福岡・京都など）は月次更新の `--with-neighbors` で取得される |
| Google Places（fetch_google_coords.py） | 所在地が行の県と一致しない候補を捨てていたため、**正しい座標も捨てていた**可能性（隣県ずれ率6.3%から、県が入っている未取得461件のうち数十件程度と推定） | 隣県・同エリア・リストの県の既存座標から10km以内なら採用。APIキーが必要なため再実行は未実施 |

10kmの根拠: ずれている170件の、リストの県で最も近い既存座標までの距離は中央値5.7km（10km以内が約7割）。
一方、隣県の同名の別施設は広島県の西条→愛媛県の西条43km、広島県の三津→愛媛県の三津37km、埼玉県の行田→千葉県の行田14kmで、10kmで全て落ちます。

### 中部エリアの座標取得（scripts/fetch_chuden_coords.py）

中部電力パワーグリッド「[系統空容量マッピング](https://gridmap.powergrid.chuden.co.jp/)」は
変電所と送電線を1本のGeoJSON（`geo_data/KRSIH001`）で配信しており、座標はWGS84の
`[経度, 緯度]` でそのまま入っています（投影変換は不要）。ここから**中部エリアのS/A 496件すべて**の
座標を取得できます。

`gridmap.powergrid.chuden.co.jp` は Azure Front Door が全パスに 403（`The request is blocked.`）を
返すため、**取得はブラウザで行います**（兄弟ホスト `powergrid.chuden.co.jp` は 200 なので、
このホスト固有の制限です）。取得済みのGeoJSONは `chuden_cache/` に同梱しているので、
`fill` 以降はネットワーク無しで再現できます。

```bash
# ① ブラウザで https://gridmap.powergrid.chuden.co.jp/ を開き、DevTools(Network)を出したまま
#    Ctrl+R でリロード → 変電所アイコンをクリック → "Save all as HAR with content" で保存

# ② HARからGeoJSONを取り出す（対象日も KRSIH002 から取り込みます）
python scripts/fetch_chuden_coords.py extract \
  --har gridmap.powergrid.chuden.co.jp.har --out chuden_cache/KRSIH001.geojson.gz

# ③ 優先リストの中部エリア行に緯度・経度・出典メモを記入（ネットワーク不要）
python scripts/fetch_chuden_coords.py fill \
  --geo chuden_cache/KRSIH001.geojson.gz \
  --list "docs/座標未取得_優先リスト.xlsx" --report chuden_fill_report.csv

# ④ 本体xlsxへ反映 → 再生成（上記 merge_coords.py と同じ手順）
```

照合は `fetch_substation_coords.py` の `normalize_name` を共用します（`変電所（１）` のような
枝番は NFKC 正規化と末尾括弧の除去で吸収されます）。取り違えを防ぐため次の方針です。

- **エリアが「中部」の行だけを対象にします。** gridmapの変電所名は他エリアの同名変電所とも一致するため（優先リスト内で60行）、エリアを限定しないと誤適用になります
- 名称は「他社変電所」「発電所」には付きません（第三者情報を排除した公表物のため）。`設備名称` があるもの＝当社設備だけが照合対象です
- 同名が複数ある場合（`瑞穂変電所（１）（２）` など同一敷地の別バンク）は**重心**を採り、出典メモに件数と最大ばらつきを残します。500mを超えて離れているものは別施設の可能性があるため採用しません

### スコア元データの定期更新（月1回の自動更新）

空容量・運用容量・予想潮流・N-1電制・出力制御（S1〜S4の材料）は、各送配電事業者が数か月ごとに更新する公表資料が元です。
`.github/workflows/capacity-refresh.yml` が**毎月5日 10:00（JST）**に、全国共通形式の変電所CSVを公開している6社と
PDFで公表している北海道の最新版を取得して本体リストを書き換え、スコア・Web用データ・地域別CSVを作り直します
（Actions タブ → `capacity-refresh` → Run workflow で今すぐ実行も可）。
同時に送電線CSVも取り直して系統トポロジー（`data/grid_topology.js`）を再生成します。

| エリア | 自動更新 | 取得元 |
|---|---|---|
| 東北・北陸・四国 | ○ | 各社ページの `sys_capa_*_tr_YYYYMM_*.csv` |
| 関西 | ○ | `interchange/takusou/pdf/154kv_(more\|less)_trans.csv` |
| 中国 | ○ | `zip/csv_*.zip` 内の `*_tr_*.csv` |
| 九州 | ○ | 開示ページの `td_*.zip` 内「変圧器CSV」 |
| 北海道 | ○ | 系統情報ページ（bid_info.html）の PDF `map_forecast_tide_list[_01〜24].pdf`（混雑状況マップ＋予想潮流等一覧表）。`scripts/hokkaido_capacity_pdf.py` が変電所の表を読み取る（要 `pip install pdfplumber`） |
| 東京・中部・沖縄 | × | 自動取得を403で拒否。手作業で確認 |

北海道のPDFについて（2026-10-20に追加）:

- 系統別の24本＋187kV以上の1本に「送電線」と「変電所」の2つの表があり、変電所の表は他社のCSVと同じ項目
  （一次・二次電圧、台数、設備容量、運用容量値、予想潮流、空容量〔当該／上位系等考慮〕、N-1電制、出力制御）を持つ。
  配電用バンク（二次6.6kV）には**当該・上位系の両方**の空容量が載るので、北海道は上位系で判定できるエリアになった
- 読み取りは単語と罫線の座標で行う。複数バンクの変電所は名前のセルが縦に結合されているため、名前は
  「どの罫線の間にあるか」で決める（縦方向の距離では3バンクの変電所と隣の変電所を取り違える）。
  名前を決められないバンクは捨てる（推測で付けない）
- 初回（2026-10-20）: 25本から459バンク行を読み取り、北海道385件のうち347件に反映（特定不可5件、本体に無い行115件）。
  それまで北海道は全件「データ無」だったが、ゲート該当（上位系0・N-1不可）251・A 30・B 5・C 3・データ無96になった。ゲート該当が
  多いのは、北海道の配電用変電所は上位系考慮の空容量が0で、かつN-1電制が「不可 ♯3（配電用変電所のため）」と公表されているため。
  由仁変電所（実績: 410万円・6ヶ月）も公表値は当該4MW・上位系0MW。この矛盾を受けて同日、ゲートを「除外」から「⚠警告」に変更した
- 同じ日に `update_capacity.py` の不具合を直した: 公表値が **0** の項目（空容量0など）を「空」と同じ扱いにして
  書き込んでいなかった。他エリアでも空容量0の行が空欄のままになっていた可能性があるため、次回の定期更新で埋まる

照合と書き換えのルール（`scripts/update_capacity.py`）:

- エリア内で、種別（変電所／開閉所など）を外した名前が一致する行だけを書き換える。同名のバンクが複数あれば二次電圧→一次電圧→
  **設備容量が既存値と一致するもの**の順に絞り、決められなければ書き換えない（「特定不可」としてレポート）
- 公表値が「－」の項目は既存値を残す（既存の予想潮流には逆算値なども入っているため、空欄で消さない）
- N-1電制の「不可 ♯3」と「不可 #3」のような表記ゆれは変更として扱わない
- 公表CSVにあって本体に無い変電所は追加しない（件数だけレポート）

照合できた行が容量データのある行の70%未満のエリアがある、取得に失敗した、またはランクが変わった行が全体の10%を超えた場合は、
main に反映せず別ブランチに置いて確認を求める Issue を起票します。普段どおりなら main に反映し、結果を Issue で知らせます。
結果は [`docs/スコア元データ_更新レポート.md`](docs/スコア元データ_更新レポート.md)、行ごとの変更は `capacity_report.csv`。

初回（2026-10-19）は、手作業で取り込んでいた6〜7月時点のデータを9〜10月時点に更新し、581行の値が変わり、57行のランクが変わりました
（S/A 1,351件 → 1,354件。主に10月15日に更新された関西）。

```bash
pip install openpyxl pdfplumber
python scripts/update_capacity.py fetch --cache-dir capacity_cache            # --areas 北海道 で一部だけ
python scripts/update_capacity.py apply --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --cache-dir capacity_cache \
  --out "data/全国変電所リスト_66kV以上_座標追加.xlsx" --report capacity_report.csv --report-md "docs/スコア元データ_更新レポート.md"
```

> 毎月1日の座標の定期更新（下記）も、変更件数が普段どおり（新規＋格上げが300件以下）なら main に直接反映し、結果を Issue で知らせます。
> 2つのワークフローは同時に動かないよう `concurrency: substation-data` で順番待ちにしています。

### 変電所座標の定期精度向上（月1回の自動更新）

`.github/workflows/substation-coords-refresh.yml` が**毎月1日 10:00（JST）**に自動で動き、
OSMの最新データで座標を取り直します。OSMは日々登録が増えるため、前回見つからなかった変電所が
後から拾えるようになります。手動で今すぐ動かす場合は GitHub の Actions タブ →
`substation-coords-refresh` → **Run workflow** を押します。

1. 座標が未取得の行、または精度が「推定」（北海道の176件・市町村レベル）の行がある都道府県について、
   25日より古いOSMキャッシュだけを取り直す（取得に失敗した県は前回のキャッシュのまま続行）
2. 未取得の行に座標を付与し、「推定」の行はOSM実測で置き換える。照合ルールは上記の
   `fetch_substation_coords.py` と同じ。推定座標から**30km以上**動く場合は同名の別施設を疑い、置き換えない
3. スコアリングxlsx・`data/substations.js`・精度レポートを再生成
4. 座標が変わったら、件数が普段どおりなら main に直接反映し、多すぎれば別ブランチに置いて確認を求める。どちらも結果を Issue で知らせる。変化が無い月は何も起きません

精度の内訳と推移は [`docs/変電所座標_精度レポート.md`](docs/変電所座標_精度レポート.md)
（推移の元データは `data/coord_quality_history.csv`）に出ます。座標精度を4段階にまとめています。

| 区分 | 座標精度の値 | 2026-10-19 時点 |
|---|---|---|
| 高 | OSM実測 / 公表資料(手動) | 3,215件（53.0%） |
| 中 | Google Places(名称一致) / OSM実測(名称一致) | 1,938件（31.9%） |
| 低 | 推定 | 176件（2.9%） |
| 無 | 未取得 | 742件（12.2%） |

レポートの「要確認」は、精度が中・低の行のうち、OSMに同名の変電所が一意に見つかり位置が1km以上
食い違うものです（データは書き換えません。地図で確かめて正しい方を `merge_coords.py --force` で反映）。
エリア別の「S/Aで低・無」は、系統ランクS/Aなのに座標が推定か未取得の件数で、手作業で調べる効果が最も大きい行です。

```bash
# 手元で同じことをする場合
python scripts/fetch_substation_coords.py fetch --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \
  --cache-dir osm_cache --upgrade-acc 推定 --max-age-days 25
python scripts/fetch_substation_coords.py apply --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" \
  --cache-dir osm_cache --out "data/全国変電所リスト_66kV以上_座標追加.xlsx" --upgrade-acc 推定 --report coord_report.csv
python scripts/coord_quality_report.py --in "data/全国変電所リスト_66kV以上_座標追加.xlsx" --cache-dir osm_cache \
  --out "docs/変電所座標_精度レポート.md" --history data/coord_quality_history.csv
```

> main への直接反映は GitHub Actions の標準権限（contents: write）で動くため、追加の設定は要りません。

### データの再生成

`data/substations.js` は自動生成ファイルです（`window.SUBSTATION_DATA` に代入するだけの素のJSなので、
`fetch` を使わず file:// で直接開いても動作します）。元リストを更新したら再生成してください。

```bash
python scripts/build_substation_web_data.py \
  --in "data/全国変電所リスト_66kV以上.xlsx" \
  --out data/substations.js
```

配点・閾値・エリア点・実績DBの定義は `scripts/substation_scoring.py` に集約されており、
xlsx版（`score_substations.py`）とWeb版が同じ定義を参照します。配点を変えるときはこのファイルだけを直し、
xlsxとJSの両方を再生成してください。

## 条例リスク定期監視（ordinance_watch）

国交省の技術的助言「国都計第7号」（2025-04-08）を受けて、危険物を含有する系統用蓄電池を
**第一種特定工作物として開発許可の対象にする自治体が急増**しています。2026-08-21の全国一括
スイープ（開発許可権者151者の全数調査）では、兵庫県・徳島県・熊本県の3県と千葉市・浜松市・
神戸市・熊本市・福島市・高崎市・太田市・所沢市・大津市・鳥取市・呉市・大分市・加古川市の
13市（権者ベース16者）で公表を確認済み。神戸市の太陽光条例への蓄電所追加（2025-07改正）や
福島市・浜松市の独自ガイドラインなど、開発許可以外の条例型規制も出始めています。

**閲覧は `ordinance.html` から**（誰でもブラウザだけで確認可能。GitHub Pages/Vercelで公開した場合も同じ）。
台帳の検索・フィルタ、案件所在地の照合（該当規制＋共通チェックリスト表示）、権者151者の調査状況、
定点監視ページの一覧が1画面にまとまっています。データを更新したら
`python scripts/build_ordinance_web_data.py` で `data/ordinances.js` を再生成してください。

案件進行中に許可要件が増えるリスクを定期的に洗うため、次の仕組みを備えています。

- `data/ordinance_registry.json` — 条例・開発許可運用・国の通知の台帳（一次情報URL付き）。
  RILG「条例の動き」等の定点監視ページ（watchpoints）も収録
- `data/kaihatsu_kyokasha.json` — **開発許可権者151者の全数リスト**（調査状況・週次ローテーション組付き）。
  技術的助言の宛先（都道府県47・政令市20・中核市62・施行時特例市22）と同一なので、
  このリストの監視で千葉市型のリスクは全国を漏れなくカバーできる
- `data/priority_munis.json` — S/Aランク変電所の所在市区町村（＝土地を探すエリアの優先監視対象）
- `docs/条例リスク台帳.md` — 台帳の閲覧用Markdown（`report` コマンドで自動生成）
- `.github/workflows/ordinance-watch.yml` — **毎週月曜9時（JST）に全URL＋定点の変更・消失を自動検知し、
  変化があれば `ordinance-watch` ラベルのIssueを起票**

```bash
# 案件の所在自治体に効く規制を照合（案件着手時・申請前に必ず実行）
python scripts/ordinance_watch.py check --pref 千葉県 --muni 千葉市

# 台帳一覧 / ページ変更検知 / 台帳Markdown再生成
python scripts/ordinance_watch.py list
python scripts/ordinance_watch.py monitor --update
python scripts/ordinance_watch.py report

# S/Aランク変電所の所在自治体リストを再生成（変電所リスト更新後）
python scripts/build_priority_munis.py
```

台帳に無い自治体でも同様の運用がいつでも始まりうるため、`check` が出力する共通チェックリスト
（開発許可担当への事前照会・所轄消防協議・例規集検索）を案件ごとに実施してください。
週次スイープ（新着検索＋権者ローテーション総当たり・約5週で全国一巡）を含む運用の全体像は
`docs/ordinance_watch_運用手順.md` を参照。
