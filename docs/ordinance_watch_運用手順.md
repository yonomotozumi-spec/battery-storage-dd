# 蓄電池条例リスク定期監視の運用手順

## 背景

国交省の技術的助言「国都計第7号」（2025年4月8日）により、**危険物（リチウムイオン電池の
電解液等）を含有する系統用蓄電池は都市計画法の第一種特定工作物に該当しうる**とされ、
これを受けて千葉市（2025年9月）・浜松市（2025年12月）をはじめ多数の自治体が
開発許可の運用を順次開始している。案件進行中に許可要件が増えて販売スケジュールに
影響する事例が実際に発生しており、**「知らない自治体で突然運用が始まる」ことを前提に**
定期的にリスクを洗う必要がある。

監視は次の3層で行う。

| 層 | 何を検知するか | 手段 | 頻度 |
|---|---|---|---|
| ① 既知ページの変更監視 | 台帳収録済みの規制の改正・詳細化・URL変更＋定点ページの更新 | GitHub Actions（自動） | 毎週月曜 9:00 JST |
| ② 新規自治体の発見スイープ | 台帳に無い自治体の新しい条例・運用開始 | Web検索（Claude定期実行 or 手動）＋開発許可権者151件のローテーション総当たり | 毎週（約5週で全国一巡） |
| ③ 案件単位の照合 | 個別案件の所在自治体に効く規制 | `check` コマンド＋窓口照会。S/Aランク変電所の所在自治体を優先監視 | 案件着手時・申請前 |

### 全国網羅の考え方

- **開発許可リスク（千葉市型）は「開発許可権者」を全数監視すれば全国を漏れなくカバーできる。**
  国交省技術的助言（国都計第7号）の宛先は都道府県47・政令指定都市20・中核市62・
  施行時特例市22の計151権者であり、`data/kaihatsu_kyokasha.json` に全数リスト化してある。
  権限移譲を受けた事務処理市町村（例: 桶川市・三田市・多治見市）は都道府県経由で通知される
  ため都道府県の調査とWeb検索スイープで補足する。
- **制定済みの独自条例**（届出・説明会型。例: 神戸市条例の蓄電所追加、福島市ガイドライン）は
  例規集横断検索と調査機関の定点で拾う: [全国条例データベース powered by eLen](https://elensv.e-legislation.jp/)
  で「蓄電」を横断検索（四半期に1回）、地方自治研究機構（RILG）の「条例の動き」ページを
  定点監視（台帳の `watchpoints` に登録済み・層①で自動監視）。
- **制定前の動き**（議会・パブコメ）は全1,741自治体では追わず、
  `data/priority_munis.json`（S/Aランク変電所の所在自治体＝実際に土地を探すエリア）に絞って見る。

## 構成ファイル

- `data/ordinance_registry.json` — 条例・開発許可運用・国の通知の台帳（一次情報URL付き）。
  `watchpoints` に定点監視ページ（RILG等）も持つ
- `data/kaihatsu_kyokasha.json` — 開発許可権者151件の全数リスト（調査状況・週次ローテーション組付き）
- `data/priority_munis.json` — S/Aランク変電所の所在市区町村（優先監視対象。`build_priority_munis.py` で再生成）
- `data/ordinance_page_state.json` — 各URLの正規化本文ハッシュのスナップショット（自動更新）
- `scripts/ordinance_watch.py` — list / check / monitor / report の4コマンド
- `scripts/build_priority_munis.py` — S/A変電所の逆ジオコード→優先自治体リスト生成
- `docs/条例リスク台帳.md` — 台帳から自動生成する閲覧用Markdown
- `.github/workflows/ordinance-watch.yml` — 週次の自動監視（層①）

## 層①: 既知ページの変更監視（自動）

GitHub Actionsが毎週月曜9:00（JST）に全URLを取得し、本文の正規化ハッシュを前回と比較する。
変更またはページ消失（404等）を検知すると **`ordinance-watch` ラベル付きのIssue** が立つ。

Issueが立ったら:

1. 該当ページを開き、何が変わったか確認する（施行日の確定・運用基準の追加・様式公開など）
2. `data/ordinance_registry.json` の該当エントリ（summary / effective_date / dd_impact /
   last_verified）を更新する
3. `python scripts/ordinance_watch.py report` で `docs/条例リスク台帳.md` を再生成する
4. 進行中案件に影響する変更なら、該当案件の担当へ共有する

手動実行: Actionsタブ → ordinance-watch → Run workflow。ローカルでは
`python scripts/ordinance_watch.py monitor`（`--update` でスナップショット更新）。

## 層②: 新規自治体の発見スイープ（毎週）

台帳に無い自治体の新規制を見つける作業。2本立てで行う。

**(a) 新着検索**（全国向け・毎週）。以下の検索を期間「1週間以内」または「1ヶ月以内」で実施:

```
"系統用蓄電池" 開発許可 取扱い
"系統用蓄電池" 第一種特定工作物
蓄電所 条例 制定
蓄電池 設置 規制 条例 届出 ガイドライン
蓄電池発電所 住民説明会 条例
site:go.jp 蓄電池 開発許可
```

**(b) 開発許可権者ローテーション総当たり**（毎週約30権者・5週で全国一巡）。
`data/kaihatsu_kyokasha.json` の `group` フィールド（0〜4）を使い、当週の
`ISO週番号 mod 5` に一致する組の各権者について「"権者名" 系統用蓄電池 開発許可」で検索する。
検索結果に権者の公式ページが出たら内容を確認し、`status`（公表あり／公表確認できず）・
`last_swept`・`url` を更新する。公表ありなら台帳 `entries` にも追加する。
初回の全数スイープは2026-08-21に実施済み（結果は各権者の `status` / `note` を参照。
検索上限で未調査のまま残った権者はローテーションで順次カバーする）。

あわせて確認する定点（層①のwatchpointsで自動監視されるものを含む）:

- 国交省 都市計画課の通知（技術的助言の改正・追補）
- 経産省「電力貯蔵装置・蓄電所を設置する場合の手引き」の更新
- 消防庁の火災予防条例（例）改正通知
- 地方自治研究機構（RILG）「条例の動き」の新テーマ（蓄電池ページ新設を監視）
- [全国条例データベース powered by eLen](https://elensv.e-legislation.jp/) で「蓄電」横断検索（四半期に1回）
- 業界ニュース（BESS NEWS、メガソーラービジネス等）の規制カテゴリ

新規に見つけたら `data/ordinance_registry.json` の `entries` に追記する（スキーマは同ファイルの
`schema` を参照。`id` は `muni-都道府県ローマ字-市町村ローマ字-連番`）。追記後に
`monitor --update` と `report` を実行してスナップショットと台帳Markdownを更新し、PRを出す。

> この層はWeb検索が必要なためスクリプトだけでは完結しない。Claude（claude.ai/code）の
> 定期実行（Routine「蓄電池条例リスク週次スイープ」・毎週月曜10時JST）に任せており、
> 手動で行う場合も同じ手順で実施する。

## 層③: 案件単位の照合（案件着手時・申請前）と優先監視

```bash
python scripts/ordinance_watch.py check --pref 千葉県 --muni 千葉市
```

案件が生まれうるエリアを先回りで見るため、S/Aランク変電所（系統スコア上位）の所在市区町村を
`data/priority_munis.json` に持つ。層②の新着検索で優先自治体名がヒットした場合は最優先で確認し、
変電所リスト更新後は `python scripts/build_priority_munis.py` で再生成する
（逆ジオコードは `geo_cache/` に蓄積されるため再実行は差分のみ）。

所在自治体に該当する台帳エントリと、全国共通の枠組み、共通チェックリストを出力する。
`--out 案件名_条例照合.md` でファイルに書き出せる。

**台帳にヒットしない＝規制なし、ではない**。checkコマンドが出力する共通チェックリスト
（開発許可担当への事前照会・所轄消防への協議・例規集検索・議会会議録検索）を必ず実施する。
特に市街化調整区域の案件は、技術的助言ベースの運用が未公表の自治体でも窓口照会で
「第一種特定工作物として扱う方針」と回答されるケースがあるため、照会結果を記録に残すこと。

## 要フォロー（一次情報未確認の候補・次回スイープで確認）

2026-08-21の全国一括スイープで名前が挙がったが、一次情報のURL確認まで至らなかったもの。

- **岐阜県関ケ原町** — 系統用蓄電池の取扱いを公表している可能性（検索結果に複数回出現。開発許可権者ではないため県経由の事務処理か独自公表かを確認）
- **広島県東広島市** — 「開発許可制度における運用基準集」に系統用蓄電池の記載がある可能性
- **青森県** — 「自然・地域と再生可能エネルギーとの共生に関する条例」（太陽光2MW以上・風力500kW以上対象）に蓄電池が含まれるか未確認
- **仙台市** — 「太陽光発電事業の健全かつ適正な導入、運用等の促進に関する条例」の蓄電池への適用有無
- **神戸市条例** — 2025年7月改正（蓄電所追加）の発効日を条例本文（g-reiki）で確認
- **未調査の権者9者** — 札幌市・仙台市・函館市・旭川市・青森市・八戸市・盛岡市・秋田市・山形市（初回スイープが検索上限で未実施。`kaihatsu_kyokasha.json` の status=未調査。週次ローテーションで優先調査。郡山市・いわき市は2026-08-21にサイト内検索まで実施し「公表確認できず」に更新済み）

なお、検索で公式ページが上位に出ない・権者でない市町村が公表しているケースは実在する
（館林市・潟上市は他自治体の検索結果への映り込みから発見）。「公表確認できず」は
「規制なしの証明」ではないため、案件着手時の窓口照会（層③）は省略しないこと。

## 台帳メンテナンスの原則

- 出典は必ず一次情報（自治体・省庁の公式ページ）。ニュース記事は `notes` に補足として書く
- 内容を確認した日を `last_verified` に必ず入れる（古い確認日のエントリは再確認対象）
- 廃止・URL移転が判明したら削除せず `notes` に経緯を残してURLを差し替える
- 施行日が「予定」の段階でも載せる（施行前に把握することが目的のため）
