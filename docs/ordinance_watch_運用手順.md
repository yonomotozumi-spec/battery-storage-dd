# 蓄電池条例リスク定期監視の運用手順

## 背景

国交省の技術的助言「国都計第7号」（2025年4月8日）により、**危険物（リチウムイオン電池の
電解液等）を含有する系統用蓄電池は都市計画法の第一種特定工作物に該当しうる**とされ、
これを受けて千葉市（2025年9月）・浜松市（2025年12月）をはじめ多数の自治体が
開発許可の運用を順次開始している。案件進行中に許可要件が増えて販売スケジュールに
影響する事例が実際に発生しており、**「知らない自治体で突然運用が始まる」ことを前提に**
定期的にリスクを洗う必要がある。

監視は次の3層で行う。

| 層 | 何を検知するか | 手段 | 頻度 |
|---|---|---|---|
| ① 既知ページの変更監視 | 台帳収録済みの規制の改正・詳細化・URL変更 | GitHub Actions（自動） | 毎週月曜 9:00 JST |
| ② 新規自治体の発見スイープ | 台帳に無い自治体の新しい条例・運用開始 | Web検索（Claude定期実行 or 手動） | 毎週 |
| ③ 案件単位の照合 | 個別案件の所在自治体に効く規制 | `check` コマンド＋窓口照会 | 案件着手時・申請前 |

## 構成ファイル

- `data/ordinance_registry.json` — 条例・開発許可運用・国の通知の台帳（一次情報URL付き）
- `data/ordinance_page_state.json` — 各URLの正規化本文ハッシュのスナップショット（自動更新）
- `scripts/ordinance_watch.py` — list / check / monitor / report の4コマンド
- `docs/条例リスク台帳.md` — 台帳から自動生成する閲覧用Markdown
- `.github/workflows/ordinance-watch.yml` — 週次の自動監視（層①）

## 層①: 既知ページの変更監視（自動）

GitHub Actionsが毎週月曜9:00（JST）に全URLを取得し、本文の正規化ハッシュを前回と比較する。
変更またはページ消失（404等）を検知すると **`ordinance-watch` ラベル付きのIssue** が立つ。

Issueが立ったら:

1. 該当ページを開き、何が変わったか確認する（施行日の確定・運用基準の追加・様式公開など）
2. `data/ordinance_registry.json` の該当エントリ（summary / effective_date / dd_impact /
   last_verified）を更新する
3. `python scripts/ordinance_watch.py report` で `docs/条例リスク台帳.md` を再生成する
4. 進行中案件に影響する変更なら、該当案件の担当へ共有する

手動実行: Actionsタブ → ordinance-watch → Run workflow。ローカルでは
`python scripts/ordinance_watch.py monitor`（`--update` でスナップショット更新）。

## 層②: 新規自治体の発見スイープ（毎週）

台帳に無い自治体の新規制を見つける作業。以下の検索を実施し、ヒットした自治体を台帳に追加する。

推奨検索クエリ（Google等で期間を「1週間以内」または「1ヶ月以内」に絞る）:

```
"系統用蓄電池" 開発許可 取扱い
"系統用蓄電池" 第一種特定工作物
蓄電所 条例 制定
蓄電池 設置 規制 条例 届出
蓄電池発電所 住民説明会 条例
site:go.jp 蓄電池 開発許可
```

あわせて確認する定点:

- 国交省 都市計画課の通知（技術的助言の改正・追補）
- 経産省「電力貯蔵装置・蓄電所を設置する場合の手引き」の更新
- 消防庁の火災予防条例（例）改正通知
- 業界ニュース（BESS NEWS、メガソーラービジネス等）の規制カテゴリ

新規に見つけたら `data/ordinance_registry.json` の `entries` に追記する（スキーマは同ファイルの
`schema` を参照。`id` は `muni-都道府県ローマ字-市町村ローマ字-連番`）。追記後に
`monitor --update` と `report` を実行してスナップショットと台帳Markdownを更新し、PRを出す。

> この層はWeb検索が必要なためスクリプトだけでは完結しない。Claude（claude.ai/code）の
> 定期実行（Routine）に任せるか、週次の定例作業として担当者が実施する。

## 層③: 案件単位の照合（案件着手時・申請前）

```bash
python scripts/ordinance_watch.py check --pref 千葉県 --muni 千葉市
```

所在自治体に該当する台帳エントリと、全国共通の枠組み、共通チェックリストを出力する。
`--out 案件名_条例照合.md` でファイルに書き出せる。

**台帳にヒットしない＝規制なし、ではない**。checkコマンドが出力する共通チェックリスト
（開発許可担当への事前照会・所轄消防への協議・例規集検索・議会会議録検索）を必ず実施する。
特に市街化調整区域の案件は、技術的助言ベースの運用が未公表の自治体でも窓口照会で
「第一種特定工作物として扱う方針」と回答されるケースがあるため、照会結果を記録に残すこと。

## 台帳メンテナンスの原則

- 出典は必ず一次情報（自治体・省庁の公式ページ）。ニュース記事は `notes` に補足として書く
- 内容を確認した日を `last_verified` に必ず入れる（古い確認日のエントリは再確認対象）
- 廃止・URL移転が判明したら削除せず `notes` に経緯を残してURLを差し替える
- 施行日が「予定」の段階でも載せる（施行前に把握することが目的のため）
